# Primer uso · Coco

1. Resuelve el perfil con `.fruti/state/current.json` y `.fruti/paths.yaml` desde la raíz. Si existe, reutilízalo y consulta [profile-additions.md](profile-additions.md) para los campos de Coco.
2. Si falta, deriva a Lima y consulta [../lima/reference/first-run.md](../lima/reference/first-run.md) y [../lima/reference/intake.md](../lima/reference/intake.md). El bootstrap vigente del paquete es `npx fruti-squad-codex init`, desde la raíz; no uses el script legacy de perfil como equivalente del modelo actual.
3. Reutiliza stack/rutas inspeccionados; pregunta solo decisiones que falten. No impongas un intake antiguo de color_law/type_law ni inventes tokens.
4. Registra únicamente hechos de datos comprobados en `coco.data_contract`. No modifica el tema, tokens o registry de Lima ni el estándar documental de Mora.
5. Para construir F3 necesita estructura aprobada, contrato y fuentes reales. Una auditoría R0 acotada puede registrar faltantes sin inicializar un sistema supuesto; no certifica esas comprobaciones.
6. Si falta scaffolder, crea la ronda autorizada sin sobrescribir una presentada. Si falta detector/auditor, aplica sus criterios manualmente y registra esa procedencia. Si falta navegador, ejecuta recuperación de `.codex/qa/pre-delivery.md`; no presenta F3 como aprobado con QA pendiente.

Continúa con [SKILL.md](SKILL.md). Todas las rutas `.fruti/` y `.codex/` son relativas a la raíz del consumidor.
